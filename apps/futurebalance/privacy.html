Resumen

Esta politica explica como FutureBalance ("la app") trata los datos del usuario. FutureBalance es una app de finanzas personales manuales para registrar ingresos, gastos, transferencias, tarjetas, pagos, deudas, presupuestos, reportes y proyeccion de saldo futuro. La app no se conecta a bancos y no solicita credenciales bancarias. Algunas funciones opcionales de cuentas compartidas pueden usar Firestore y Cloud Functions para crear espacios, aceptar invitaciones y leer datos compartidos entre miembros autorizados.

Desarrollador y contacto de privacidad: ACKA94 / Carlos Alcivar, support@ka94studio.com. Paquete Android: com.futurebalance.micartera.

Datos que tratamos

Categoria Ejemplos Origen
Cuenta e identidad UID de Firebase, correo, nombre, foto de perfil si Google la entrega, proveedor de acceso y timestamps basicos. Firebase Authentication, Google Sign-In o registro por correo.
Perfil remoto basico Documento de usuario y perfil principal para identificar cuenta, plan/licencia y soporte. Cloud Firestore con reglas por usuario.
Cuentas compartidas opcionales Espacios compartidos, membresias, roles, carteras compartidas, movimientos compartidos por mes, invitaciones/codigos y estado de suscripcion Shared. Datos ingresados por usuarios autorizados y operaciones procesadas mediante Firestore y Cloud Functions.
Datos financieros manuales Carteras, tarjetas, categorias, movimientos, transferencias, compras con tarjeta, pagos, deudas, prestamos, cuotas, paquetes, presupuestos y proyecciones. Datos ingresados manualmente por el usuario; en Free/Pro se guardan localmente en SQLite/Drift.
Backups y exportaciones Archivos JSON/ZIP de respaldo, CSV exportado, imagenes personalizadas de categorias y paquetes de restauracion. Acciones iniciadas por el usuario o backup automatico Pro cuando este habilitado.
Compras y plan Estado Free/Pro, productos Pro, suscripciones Shared cuando existan, token de compra enviado para verificacion, hashes de token guardados por backend, verificacion y cambios administrados de plan. Google Play Billing, Cloud Functions, Android Publisher/RTDN y Firestore.
Diagnostico y uso tecnico Eventos tecnicos, version, fallos, rendimiento y datos necesarios para estabilidad. Firebase Analytics, Crashlytics y servicios del sistema.
Soporte y avisos gestionados Tickets, mensajes, estado de soporte, avisos de mantenimiento de servicio o actualizaciones administradas. Funciones de soporte/ACKA94 y datos enviados por el usuario.

Como usamos los datos

  • Crear, proteger y recuperar la cuenta del usuario.
  • Guardar localmente los datos financieros que el usuario registra.
  • Calcular saldos, reportes, presupuestos, proyecciones y pagos exigibles sin conexion bancaria.
  • Crear backups locales, compartir exportaciones CSV y guardar backups en Google Drive AppData cuando el usuario lo autoriza.
  • Verificar compras Pro y aplicar beneficios sin autoconceder licencias desde el cliente.
  • Verificar suscripciones Shared y permitir crear, aceptar o leer espacios compartidos cuando el usuario use esa funcion.
  • Aplicar roles de cuentas compartidas para limitar lectura, escritura y administracion a miembros autorizados.
  • Programar notificaciones locales de pagos, deudas, prestamos, paquetes, presupuestos, proyeccion y actualizaciones.
  • Detectar fallos, mejorar estabilidad y proteger la app contra abuso.
  • Resolver tickets de soporte y mostrar avisos operativos administrados.

Permisos y funciones sensibles

Internet

La app usa Internet para Firebase Auth, perfil remoto basico, verificacion de plan, Google Sign-In, Google Drive AppData, consultas de tipo de cambio, actualizaciones, soporte y funciones opcionales de cuentas compartidas.

Notificaciones

La app puede solicitar POST_NOTIFICATIONS para avisos locales. El usuario puede controlar canales y recordatorios desde Ajustes y desde cada registro compatible.

Archivos e imagenes

La app puede abrir selectores del sistema para backups, exportaciones CSV e imagenes personalizadas de categorias. No guarda PIN, contrasenas, tokens bancarios ni datos biometricos en texto plano.

Servicios de terceros

  • Firebase Authentication: inicio de sesion por Google o correo/contrasena.
  • Cloud Firestore: perfil basico, plan/licencia, soporte, avisos administrados, membresias y datos de cuentas compartidas; no es fuente operativa principal de datos financieros personales Free/Pro.
  • Cloud Functions: verificacion de compras, operaciones de soporte/admin, creacion o aceptacion de espacios compartidos y controles backend de suscripcion Shared.
  • Firebase Crashlytics y Analytics: estabilidad, diagnostico y eventos tecnicos. No deben capturar contenido financiero sensible.
  • Google Drive AppData: backups de datos operativos cuando el usuario guarda/restaura desde Drive o cuando Pro habilita backup automatico.
  • Google Play Billing: compra Pro, restauracion/sincronizacion de compra y suscripciones Shared cuando se ofrezcan.
  • Google Play Developer API / RTDN: validacion backend de compras, suscripciones, renovaciones, cancelaciones, reembolsos y estados fuertes.
  • api.frankfurter.dev: tasas de cambio publicas sin API key; no requiere enviar movimientos financieros del usuario.

La version actual de FutureBalance no declara Google Mobile Ads como SDK activo. Si se agregan anuncios en una version futura, esta politica y el formulario Data safety se actualizaran antes de publicar esa version.

La app no vende datos personales ni datos financieros del usuario.

Seguridad

FutureBalance usa autenticacion de Firebase, reglas Firestore por usuario, almacenamiento local privado mediante SQLite/Drift, transacciones locales para restauracion, validaciones antes de importar backups y cifrado de transporte cuando los datos viajan por red. Los datos financieros personales Free/Pro son local-first. Las cuentas compartidas usan reglas por membresia, limites de lectura por pantalla/mes y Cloud Functions para operaciones sensibles; no se deben abrir escrituras amplias desde el cliente.

Retencion y eliminacion

Conservamos datos mientras la cuenta este activa o mientras sean necesarios para prestar el servicio, respaldar compras, prevenir fraude, resolver soporte o cumplir obligaciones legales. Los datos guardados solo en el dispositivo pueden eliminarse borrando datos de la app o desinstalandola. Los backups exportados o compartidos por el usuario deben eliminarse desde el lugar donde fueron guardados. Los datos de espacios compartidos pueden conservarse mientras el espacio siga activo para otros miembros autorizados; al eliminar una cuenta se revisan membresias, roles y datos asociados para eliminarlos, desvincularlos o anonimizarlos cuando corresponda sin afectar indebidamente a otros usuarios del espacio.

Para solicitar eliminacion de cuenta y datos asociados, usa la pagina: Eliminar cuenta de FutureBalance.

Menores

FutureBalance no esta dirigida a ninos. Si crees que un menor envio datos personales sin autorizacion, escribe a support@ka94studio.com.

Cambios

Podemos actualizar esta politica cuando cambien funciones, proveedores, permisos o practicas de datos. Publicaremos la version vigente con su fecha de actualizacion.

Nota para Play Console: esta politica debe mantenerse coherente con el formulario Data safety, la declaracion de cuenta, permisos, compras, suscripciones Shared, datos compartidos y la pagina de eliminacion configurada para FutureBalance.
